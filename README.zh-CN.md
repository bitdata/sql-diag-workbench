# SQL Diagnostic Workbench

[English](README.md) | 简体中文

一款用于 SQL 结果排错与性能分析的桌面工具。将复杂查询拆成可查看、可执行的片段，通过中间结果逐步定位数据在哪里丢失、重复或膨胀。

**个人与企业均可免费使用 · AGPL-3.0 开源许可，另提供商业授权选项。**

## 查询没结果、结果不对，或者运行太慢？

排查复杂 SQL 时，经常需要反复注释 JOIN、单独执行子查询、核对中间行数。SQL Diagnostic Workbench 把这些步骤放到同一个工作区，帮助你沿着查询结构逐步缩小问题范围。

- **查不到预期数据**：检查中间结果，定位哪个 JOIN 或过滤条件排除了目标数据。
- **结果重复、行数异常增多**：比较关联前后的结果，排查导致行数膨胀的环节。
- **改写后不确定结果是否一致**：并排比较原查询与修改后的片段，检查结果与性能变化。
- **查询执行缓慢**：查看执行计划与诊断提示，寻找值得优先检查的执行环节。

## 核心功能

### 拆开复杂 SQL，逐段查看结果

将 SQL 解析为可探索的结构，查看其中的 CTE、子查询、JOIN 和过滤条件。选中片段即可执行并查看数据与行数，减少手工拆 SQL、复制到多个窗口执行的操作。

从有数据的片段开始，逐步检查后续关联与过滤，观察结果从哪一步发生变化。具体可用的拆解操作取决于 SQL 结构。

### 并排比较两种写法

选择两个片段进行 A/B 比较，在同一个数据库连接下分别查看结果与性能。可以比较同一查询中的片段，也可以跨标签页比较，方便检查一次 JOIN 调整、条件修改或查询改写带来的影响。

修改片段时会打开新标签页，保留原始 SQL，便于继续尝试其他写法和回看原查询。

### 结合执行计划分析慢查询

在性能模式中查看预估执行计划与诊断提示，了解数据库准备如何执行查询。PostgreSQL 还支持实际执行计划，可进一步查看查询运行时的表现。

**实际执行计划（ANALYZE）会执行查询**，可能给数据库带来负载，请选择合适的执行时机。

### 保存排查现场，下次继续

在本地保留连接、查询工作区和历史记录，正常关闭后可以继续之前的排查。通过历史清理设置管理保存时间和占用空间。

界面支持简体中文和英文，并提供浅色、深色和高对比度主题。

## 支持范围

当前支持的桌面平台为 **Windows x64**。

| 数据库 | 查询执行 | 预估执行计划 | 实际执行计划 | 已测试版本 |
| --- | --- | --- | --- | --- |
| PostgreSQL | 支持 | 支持 | 支持 | 16.14 |
| MySQL | 支持 | 支持 | 本工具暂不支持 | 8.0.46 |

工具主要用于诊断 `SELECT` 查询，包括带 `WITH` 子句的查询。SQL 解析与拆解存在适用范围，支持上述数据库不代表支持其所有 SQL 写法或所有版本。

无需连接数据库即可解析 SQL；执行查询和获取执行计划需要连接对应的数据库。

## 后续功能规划

- **更深入的查询性能分析与优化**：在现有执行计划查看能力上，结合原查询的运行指标定位瓶颈，提供可验证的优化建议；检查改写前后的结果是否一致，并在可比较的条件下评估性能变化。
- **更多数据库支持**：在 PostgreSQL 和 MySQL 之外，逐步扩展数据库适配，让更多数据库用户也能使用 SQL 拆解、中间结果排查与执行计划分析。

以上为后续方向，尚未全部提供；具体数据库、功能范围和发布时间以版本说明为准。

## 安装

在 [GitHub Releases](https://github.com/bitdata/sql-diag-workbench/releases) 查看可用版本与 Windows 安装包。

1. 从发布页面下载 Windows x64 安装包。
2. 运行安装程序，启动 **SQL Diagnostic Workbench**。
3. 在 **设置 → 语言** 中选择偏好的界面语言。

Windows 安装包自带 Java 运行环境，无需单独安装 Java。

## 开始使用

1. **连接数据库。** 打开连接管理，创建 PostgreSQL 或 MySQL 连接，填写主机、端口、数据库、用户名和密码，测试后保存。建议使用只读数据库账号进行查询诊断。
2. **粘贴 SQL。** 打开查询标签页，粘贴待排查的 SQL，并选择对应的 SQL 方言。
3. **解析查询。** 点击 **解析** 或按 `Ctrl+Shift+Enter`，查看查询结构。
4. **查看中间结果。** 选中片段，在数据模式下执行。沿相关的 JOIN、过滤条件或子查询逐步查看结果变化。点击 **执行 SQL** 或按 `Ctrl+Enter` 可执行当前编辑器中的 SQL。
5. **比较不同写法。** 对片段选择 **比较**，再从树中或其他标签页选取另一个片段。两侧使用选定的同一个连接执行。将片段修改为不同查询时，会新开标签页并保留原始 SQL。
6. **分析性能。** 切换到性能模式，获取预估执行计划。对于 PostgreSQL，还可以获取实际执行计划，查看查询运行时的表现。

可以在 **设置** 中调整查询超时和结果行数上限。界面显示的结果可能受到行数限制；诊断提示与部分结果用于辅助排查，不能据此断定查询正确或某行数据不存在。

## 常用快捷键

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl+Shift+Enter` | 解析 SQL |
| `Ctrl+Enter` | 执行当前编辑器中的 SQL |
| `F5` | 在数据模式下执行选中的片段 |
| `Ctrl+Shift+F` | 格式化 SQL |
| `Ctrl+N` | 新建查询标签页 |

## 数据保存与历史清理

连接配置、工作区和历史记录保存在本地。执行查询时，SQL 会发送到你选择的数据库连接。

Windows 下保存的密码会按当前 Windows 用户加密。将应用数据迁移到另一个 Windows 账号后，需要重新输入密码。

正常关闭应用时会保存打开的工作区；强制结束进程或断电可能导致近期修改未保存。默认卸载操作会保留应用数据。

在 **设置 → 数据保留** 中，可以配置保留天数和存储上限、预览或手动清理旧历史。修改后点击应用，使清理策略生效。当前工作区及恢复所需的记录会受到保护。
